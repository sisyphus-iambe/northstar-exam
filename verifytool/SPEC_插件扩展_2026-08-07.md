# verifytool 插件式扩展规格 (2026-08-07 深夜)

**目标**: 把 verifytool 从"单功能质检仪(产品①)"升级为"一个程序 + 插件式扩展",
把产品②模板库 / ③自动考卷构造器 / ④剪枝调度 组装进同一 CLI。
产品⑤(自主发现平台)不在本规格内 — 研究资产, 未建成(如实)。

**权威约定(沿用现有)**:
- 零改动 `calibrator/` `programs/` 现有文件(含 experiments/ 下已有实验脚本)
- verifytool 现有主命令 `python3 -m verifytool <v.py>` 行为逐字节不变(向后兼容)
- 新增代码只允许新增文件; 单验证器确定性重跑逐字节一致(唯一非确定 = elapsed_seconds)

---

## 1. CLI 设计

```
python3 -m verifytool <v.py> [--runs N] [--out PATH]   # ① 质检主命令(现状, 不变)
python3 -m verifytool templates [list|info <名>]        # ② 模板库入口
python3 -m verifytool exam <模板名> [--runs N]          # ② 考任意模板(复用主管道)
python3 -m verifytool construct --rule <rule.json> <数据csv>   # ③ 构造器(离线规则执行)
python3 -m verifytool prune [--world synthetic|--cands <p.json>] [--budget B]  # ④ 剪枝调度
```

无子命令 → 进入原主命令(默认), 保证旧用法不破坏。

## 2. 子命令 ② templates / exam(模板库统一入口)

**现状**(探索确认): 模板在 `calib_exp/programs/` 14 个文件(9 考卷模板 + 5 错误对照),
统一契约 `chi2_pvalue(observed: 2D计数表) -> float`; 元信息只有散落的 `NAME` 常量
(且不一致: template_slope.NAME="slope" 其余="template_*"); 无统一清单。
另有 experiments/qualcheck_realworld/programs_real/ 8 个(实验 05 演示样)。

**规格**:
- 新增 `templates.py`(verifytool/ 内):
  - `TEMPLATE_REGISTRY`: 显式注册表(不目录扫描), 9 模板 + 5 错误对照 + 8 演示样,
    条目 = {name, path, kind(考卷模板/错误对照/演示样), desc(取 docstring 首行)}
  - `list_templates()`: 输出表格(name/kind/desc), 统一 NAME(去掉 template_ 前缀)
  - `load_template(name)`: importlib 加载 + 契约检查(chi2_pvalue 可调用), 复用 loader.py 的检查逻辑
- `exam <模板名>`: 加载后走现有 `run_verify.run_verify` 全管道(四层+能力地图+盲点)
  → 输出 HTML+JSON(与主命令同格式, 文件名前缀 exam_<模板名>)
- 语义说明(如实): exam 考的是模板的"实现正确性", 模板库自校准档案
  (template_exam.py 9 域 L1-L4, 9 模板全 FAIL) 是另一套口径 — 工具输出注明差异。

## 3. 子命令 ③ construct(自动考卷构造器, 离线版)

**现状**(探索确认): 9a 的 R1 规则 = LLM 输出的 JSON 结构化规则
`{stat: a|prr|chi2, year, op: >=|<=, value}`, 执行侧纯函数
(rule_predicates/cond_holds/metrics_from_pred/make_split, bootstrap_monotone/run_bootstrap_monotone.py)。
acc 0.994 = R1 规则 held-out 准确率(0.99375), 与判据1 信号定义对拍, 与 calibrator 无关。
LLM 循环(LLM 调用 + FAERS/scripts 硬编码绝对路径)有 API 成本且非确定 — 不可作默认路径。

**规格**:
- 新增 `constructor.py`(verifytool/ 内):
  - 从 bootstrap_monotone 抽离线纯函数(rule_predicates/cond_holds/metrics_from_pred/
    make_split 同语义实现), **不 import 原实验脚本**(避免 FAERS 硬编码路径依赖)
  - 输入: `--rule <rule.json>`(R1 同 schema)+ 数据 CSV(2x2 四格表格式:
    year, drug/信号列, 事件/非事件计数)
  - 输出: 规则在数据上的评估(TP/FP/TN/FN + accuracy), JSON+HTML 简版
- 语义说明(如实): 本子命令 = 9a 的"规则执行+评估"离线化; "LLM 自动生成规则"
  部分不接入(有 API 成本), 规则 JSON 由用户提供 — 构造器 = 确定性执行器。
- 未来扩展(标注, 不做): 自动构造"验证器考卷"型规则(当前只支持信号检测规则型)。

## 4. 子命令 ④ prune(剪枝调度)

**现状**(探索确认): design_prune/design_prune_v7c.py 纯函数零外部依赖最干净:
`gen_seed(seed)` 合成世界生成 / `topup_crit_recursive(p_cur, n_topup, next_p)`
临界救援(MAP_CRIT) / `combine_k(ps)` Fisher 合并 / `bh_correct(p_final, m, alpha)`。
finance_weaksig 的 x04 隐式 importlib 依赖 + 数据 manifest md5 — 太重, 不接。

**规格**:
- 新增 `prune.py`(verifytool/ 内): 实现(或等价实现, 与 v7c 纯函数逐位一致):
  - `run_schedule(p_first, p_pool, budget, arm)` → FULL/MAP_CRIT/ONESHOT 三臂调度结果
  - `combine_k` / `bh_correct`(Fisher 合并 + BH 判定)
  - `gen_seed(seed)` 合成世界(200 候选: 70 超弱/70 中弱/30 盲点M7/30 盲点M6)
- 输入: `--world synthetic`(默认, 演示模式, 复现 v7 口径)或 `--cands <p.json>`
  (用户提供候选 p 值数组 → 三臂调度比较)
- 输出: 三臂真检出/fp 对比 + 调度轨迹(JSON+HTML), 判据口径与 v7/4h 一致
  (BH α=0.05, 预算 B 默认 = 候选数, FULL=均匀随机加投, MAP_CRIT=临界优先)
- 语义说明(如实): 本子命令 = 剪枝调度的通用执行器; 4h 结论"部分成立"照录
  (方向同向, 零 fp 未复制, finance_weaksig/ 结果引用)。
